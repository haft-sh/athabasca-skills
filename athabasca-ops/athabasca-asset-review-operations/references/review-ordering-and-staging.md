# Review ordering and staging

Condensed notes from a Good Boy asset-review session.

## Durable takeaways

- When a user asks for a review queue in **descending order**, preserve that exact traversal order rather than substituting API order or creation time.
- For iterative variant review, start with the highest-numbered/latest candidate when the user explicitly asks for descending inspection.
- If one prop/reference is already shipped, use it as the evaluation anchor for adjacent brand, packaging, and character-sheet review.
- Distinguish clearly between:
  - **canonical / ship-ready** assets
  - **good exploration** boards
  - **useful but not final** continuity/layout boards
  - **needs redo** outputs

## Useful phrasing pattern

- "good exploration reference" for boards that establish direction but do not yet lock the design
- "useful continuity/layout reference, not final printable art" for packaging or brand boards with garbled text or unstable microdetails
- "production-usable with minor multi-view drift" for character/prop sheets that broadly preserve canon but still show normal generation variance

## Sequence pattern

1. ship the strongest canonical prop/reference first
2. review dependent support assets relative to that canon
3. preserve the requested queue order in the report
4. end with a direct recommendation about what to lock next
