# UI product mockup second-pass pattern

Use this pattern when image generation produces a beautiful but too-abstract product mockup.

## When to trigger

- The first pass looks like portfolio concept art rather than a plausible shipping UI
- Text is too soft or tiny to read as intentional UI
- Reflections, haze, glare, or dramatic camera treatment obscure the interface
- The product looks like a fashion render or editorial scene more than a real app

## Second-pass correction block

Append a correction paragraph like:

> Second-pass guidance: keep the premium photographed-product energy, but increase UI legibility, product realism, and faithful information architecture. The interface should read immediately as a plausible shipping product, not an abstract concept render. Text blocks, tree rows, and controls should be crisp enough to feel intentional. Reduce glamour haze, reduce fake reflections, and avoid surreal camera angles.

For mobile reader variants, adapt the same idea toward typography and believable navigation:

> keep the photographed premium presentation, but make the reading UI more believable, more readable, and less like editorial concept art. Typography should feel intentional and calm. Reduce cinematic glare and abstract reflections. The interface should look like a real mobile reader app that could plausibly ship.

## Practical rule

Keep the user's style goal, but explicitly constrain:
- legibility
- believable layout density
- plausible hierarchy
- restrained reflections/glare
- reduced lens distortion

Do not throw away the first pass. Save both passes when the user may want to compare polish versus realism.
